# ADR-006: ファイルフォーマット

**日付**: 2026-02-22
**ステータス**: Accepted

---

## コンテキスト

ユーザーが作成した路線データをローカルに1ファイルとして保存・読み込みできる必要がある。以下の制約のもとでフォーマットを決定する。

- ローカルへの1ファイル保存・読み込みが唯一の要件
- ファイルサイズ・互換性に制約なし
- MVPはベータ版として破壊的変更を許容する

---

## 決定事項

### フォーマット: JSON（テキスト）

`RailwayFile` インターフェースをそのままJSONシリアライズしたものをファイルとして保存する。

### ファイル拡張子: `.rdia`（Railway Diagram）

### バージョニング戦略

`metadata.version` にセマンティックバージョン文字列を持たせる。

- **MVPおよびファーストリリースまで**: バージョン番号を持つのみ。互換性のないバージョンはエラー表示
- **ファーストリリース後**: マイグレーション関数で古いバージョンを自動変換
- **ベータ期間中**: 破壊的変更を許容

---

## 却下した選択肢とその理由

| 選択肢 | 却下理由 |
|--------|---------|
| JSON + gzip圧縮 | ファイルサイズに制約がなく、デバッグ時に読めないコストが上回る |
| MessagePack等バイナリ | 追加ライブラリが必要、人間が読めない、制約のない状況では過剰 |

---

## 理論的根拠

素のJSONはTypeScriptのデータモデルと直接対応するため、シリアライズ・デシリアライズのロジックが最小になる。デバッグ時にファイルをそのまま読めることは開発初期段階で特に価値が高い。ファイルサイズの制約がない以上、圧縮やバイナリ化のコストを払う理由がない。

---

## 未決事項（ファーストリリース後に設計）

- マイグレーション関数の設計とバージョン管理戦略
- JSONスキーマバリデーション（zod等）の導入検討
- OuDia形式からの変換機能
